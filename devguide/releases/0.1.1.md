## Qualification procedure and publication boundary

Qualification required an exact-source main workflow with quality, shared candidate
build, installed Conda on Linux x86_64/macOS arm64 × Python 3.11–3.14, the Linux 3.14
wheel, measured main coverage and all eight latest-public-provider cells. Routine
pushes run only one latest cell; a manual exact-head test run supplies the complete
latest matrix. Record component governance for the same source. Retain the original
candidate files and their hashes; never rebuild a file to reuse an old receipt.

The optional real-MolSysMT test may skip where that scientific provider is absent.
Recorda/Ackredit qualification must execute. No hydrogen engine, new scientific
assessment or completed MOLI #28 invocation agreement is implied.

A public source tag is separate from a GitHub Release, Conda upload and archival.
This work does not select package publication. The manual publisher defaults to
read-only readiness; publishing an original qualified file still requires its own
authorization, coordinate/write checks, independent public poststate and clean
public-channel installation. No public PyPI route is planned.
